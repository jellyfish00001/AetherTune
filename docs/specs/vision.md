# AetherTune 願景、優先順序與成功標準

**文件邊界：**本頁是使用者目標、長期願景、優先順序與階段路線的唯一 owner。任務狀態與證據只在[目標與任務進度](../status.md)；`LIVE` 分類仍由 [LIVE gate](live-gate.md) 擁有；決策原因見[決策紀錄](../reference/decision-log.md#2026-11-03-vision)。

來源：2026-11-03（Asia/Taipei）使用者對 10 個方向問題的回答。後續調整願景時更新本頁並在決策紀錄新增一筆，不只記在 Agent 記憶。

## 終極目標

做出本地、即時、自然到**聽眾聽不出是變聲器**的女性聲線變聲與語音生成工具，先用於直播，之後擴充到影片配音。

## 使用者決定（2026-11-03）

| # | 主題 | 決定 |
|---|---|---|
| 1 | 即時門檻 | 新增「即時（RT）」層級：**麥克風進聲 → 輸出出聲**整段端到端 100–300ms 為正式目標。既有 `<= 5 秒` LIVE gate 不改寫，兩者分開判定 |
| 2 | 自然度驗收 | 使用者本人聽過認可即可，不要求盲測統計 |
| 3 | 主力引擎 | 未定。先實測 RVC、Seed-VC、MeanVC2、X-VC 各自的延遲上下限與音質，再選主力（BENCH-01） |
| 4 | 效能基準硬體 | 效能數字以 PC1（RTX 5060 Ti 16GB）為準 |
| 5 | 優先順序 | 先做「實體麥克風、即時、能用」；模組化與 UI 整理延後。**目前先不在 PC1 執行**，開發與初測在 PC2（RTX 2060），PC1 驗證之後再排 |
| 6 | TTS | 目標是即時（串流）TTS，可犧牲部分音質、延遲優先；完全自然的音色品質之後再研究 |
| 7 | 第一個輸出目標 | Discord |
| 8 | 主要用途 | 先做直播（初期可接受較高延遲），之後再加影片配音 |
| 9 | 目標聲線 | 自然的女性聲音，不模仿特定人物；可另選一個參考角色／聲音作為比較目標並定義可量測參數（待研究） |
| 10 | 交付形式 | 先做自用開發版，不做 installer 或產品 |

## 成功標準

| 層級 | 條件 | 判定方式 |
|---|---|---|
| 可用（直播初版） | 實體麥克風 → VC → Discord 能連續使用；延遲可高於 300ms 但穩定、無明顯斷音 | 使用者本人在 Discord 實際使用並認可；附端到端延遲量測 |
| 即時（RT） | 同一路徑端到端 100–300ms（PC1 量測） | 以實測 artifact 計算 mic in → output 延遲；PC2 數字只作參考 |
| 自然 | 女性聲線自然到聽不出是變聲 | 使用者本人聽評認可；可附參考聲音的客觀參數比較 |
| 正式 LIVE | 依 [LIVE gate](live-gate.md) 既有條件 | 不因 RT 或可用層級而自動升格 |

## 路線階段

1. **P1 量測與選型（PC2）**：BENCH-01 引擎延遲／音質矩陣；VOICE-01 定義女性目標聲線與比較參數。
2. **P2 直播可用（PC2）**：E2E-01 實體麥克風 → 選定引擎 → Discord 端到端，先求穩定可用。
3. **P3 即時化（PC1）**：在 PC1 重測並優化到 100–300ms；PC1 開跑前需使用者同意。
4. **P4 即時 TTS**：TTS-RT-01 串流 TTS，延遲優先。
5. **P5 品質與擴充**：完全自然音色、影片配音、模組化／UI 整理；產品化（SHIP-01）不在近期範圍。
