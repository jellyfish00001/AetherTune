# AetherTune 應用功能需求單

本檔用使用者的操作目的列出「應用要能做什麼」，方便逐項確認需求；列在這裡不代表已實作或已驗收。詳細行為以[產品規格](app-requirements.md)為準，完成程度與下一步只查[任務進度](../status.md)。每項連回既有 F 功能 ID，不另建一套進度或驗收表。

1. **文字轉語音（TTS）**　[對應 F03](app-requirements.md#f03)
   - 輸入文字、選擇聲音與引擎，產生語音並送到指定輸出裝置；文字發聲不要求開啟麥克風。
   - 使用 CosyVoice2、Breeze TTS 2 等已接入引擎；依引擎實際能力提供語言、聲音及參數選擇。
   - 提供完整輸入框、精簡快速輸入、常用文字及收藏；中文輸入法選字時不誤送。

2. **語音轉語音／即時變聲（VC）**　[對應 F02](app-requirements.md#f02)
   - 從麥克風取得語音，轉成指定聲線並輸出，保留原說話內容與表演，而非先轉成文字重念。
   - 選擇 Seed-VC、MeanVC2、X-VC 的參考聲音路線，或 RVC 的角色模型路線；依引擎支援調整音高等參數。
   - 支援開始、停止與切換引擎；RVC 指定 WAV 的測試流程與麥克風流程分開顯示。

3. **語音轉文字再轉語音（STT → TTS）**　[對應 F04](app-requirements.md#f04)
   - 麥克風語音經斷句與辨識轉成文字，再用選定聲音重新生成語音。
   - 與手動文字共用發聲佇列、音效及輸出設定，保留原辨識文字與來源。
   - 同一段語音不重複辨識；停止、取消及錯誤處理能追蹤。此路線重新生成表演，與第 2 項的即時變聲分開。

4. **可調整混音與音效**　[對應 F06](app-requirements.md#f06)
   - 調整原音／效果音的乾濕比例、輸出增益、EQ、壓縮與殘響；這是目前規格中混音控制的範圍。
   - 每個引擎分別保存音效，可啟用、停用及重設；修改設定不改變已接受的發聲工作。
   - 可銜接既有外部 Audio Rack／VST；需要人工操作的外部效果清楚標示。

5. **單獨語音轉文字（STT）**　[對應 F04](app-requirements.md#f04)
   - 辨識自己的實體麥克風，以及一個指定遠端音訊來源，區分 ME／REMOTE。
   - 切換或停止變聲時，逐字辨識服務可保持運作。
   - 避免把變聲後輸出或 TTS 播放再次當成自己說話，防止回授與重複紀錄。

6. **聲音與模型管理**　[對應 F05](app-requirements.md#f05)
   - 用聲音目錄選擇角色或參考聲音，不必每次輸入模型及音檔路徑。
   - 匯入、檢查及管理聲音資料，區分 RVC 模型／index 與其他引擎的參考音訊／文字。
   - 保留素材來源、語言與使用限制，提示缺檔、不支援或尚未準備完成。

7. **引擎參數與情境預設**　[對應 F02／F05](app-requirements.md#f05)
   - 只顯示目前引擎真正支援的參數；基本與進階設定分開。
   - 保存及載入模式、聲音、模型、裝置、參數、音效與 STT 的完整組合。
   - 設定失效時指出原因；需要重新啟動才生效的項目明確提示。

8. **音訊裝置、路由與自己監聽**　[對應 F06](app-requirements.md#f06)
   - 分別選擇麥克風、主要輸出及自己的耳機／喇叭監聽。
   - 可把聲音送到虛擬音訊線路，供 Discord、OBS 或其他接收端使用。
   - 裝置名稱容易辨認，保留進階裝置選項；自己監聽可獨立開關並避免回授。

9. **語音佇列與播放控制**　[對應 F03](app-requirements.md#f03)
   - 文字可立即發聲或加入先進先出的等待佇列；提供插播與忙碌時拒絕新請求的策略。
   - 可排序、移除、立即播放指定項目、停止目前語音或清除等待項目。
   - 每筆保留提交時的聲音、路由及音效；生成失敗、取消與播放完成清楚區分。

10. **逐字稿、Session 與歷史查詢**　[對應 F07](app-requirements.md#f07)
    - 顯示內容、來源與時間，支援捲動、暫停、篩選、複製及清除畫面。
    - 跨 Session 搜尋及分頁，匯出 TXT／JSONL，SRT 為選配；清畫面不刪除歷史資料。
    - 只有完成播放的 TTS 內容標示為已發聲，失敗或取消的工作另保留紀錄。

11. **桌面介面與快捷操作**　[對應 F01](app-requirements.md#f01)
    - 完整、精簡與迷你三種視窗，依場合切換；主要操作與停止入口容易找到。
    - 支援置頂、透明度、拖曳、鎖定、滑鼠穿透、系統匣與快捷鍵，且能解除穿透或完整退出。
    - 提供繁中／英文及鍵盤操作；切換畫面或語言不清掉草稿，也不重複提交語音。

12. **執行狀態、效能與錯誤復原**　[對應 F08](app-requirements.md#f08)
    - 看得懂目前是在排隊、載入、生成、播放或停止，並顯示已等待時間。
    - 顯示有實際量測來源的延遲、資源及執行狀態；沒有資料就不填假數字。
    - 錯誤提供原因、可做的下一步與診斷紀錄；提交逾時避免重複發聲。

13. **設定保存、資料管理、安裝與更新**　[對應 F07／F09](app-requirements.md#f09)
    - 保存語言、視窗、聲音、音訊及逐字稿等偏好，重新啟動後依設定恢復。
    - 支援資料版本管理、備份還原及確認後清理；更新失敗可復原。
    - 提供明確的安裝與環境檢查流程，區分開發版、安裝包與可攜版的交付範圍。

14. **Agent 回覆與自動發聲擴充**　[對應 F10](app-requirements.md#f10)
    - 規劃把 Agent 產生的文字接入既有語音佇列，追蹤回覆來源與發聲結果。
    - Agent API、自動回覆、Personality 與常用語快捷鍵分項實作。
    - 啟用權限、停止／取消及防回授機制完備後，才開放自動發聲。

## 所有功能共同遵守的品質需求

- **好操作：**操作順序清楚，載入、空白、忙碌與錯誤都有可理解的回饋。
- **有效率：**先量測，再改善啟動、生成、畫面更新與資料處理；同時守住音質、取消及資源清理。
- **容易維護：**程式與資料責任模組化、降低耦合，介面與資料版本有明確規則。
- **進度可追蹤：**人可由需求查到實作程度；Agent 可找到 owner、測試、證據及下一步。共通規格為 N01～N04，狀態統一記在[任務進度](../status.md)。
